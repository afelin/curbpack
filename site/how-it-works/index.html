How it works

Plain speak. Abbreviations expanded once.

1. Rule pack

A rule pack is a JSON file of checks (files present, banned dependency versions, forbidden text patterns). Packs encode policy: house rules, CRA-style annex drafts, or sector templates. The binary does not hard-code an industry.

2. Local check

First move on a product repo: cyberready init then cyberready check. Check evaluates packs against your git repository on disk. Results are dual: machine JSON (Gate Failure list) and markdown humans/agents can read. Exit code 0 means gates green; 1 means findings remain.

3. Review pack

prepare-release writes a review pack: layered reports, optional software bill of materials (SBOM) summary, and a buyer one-pager HTML. Daily check does not open or regenerate that HTML page.

4. Human sign-off

A person reads the evidence and may run attest to bind a reproducible state hash into Git Notes. Unsigned attestations are labeled unsigned — not “verified.”

See a committed sample one-pager (generated once in-repo): samples/onepager.html. Do not re-run demo just to reopen the browser.
