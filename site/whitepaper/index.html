CyberReady+ White Paper

Local evidence preparation for human review — architecture, packs-as-data, dual representation, trust boundaries, limitations.

CyberReady prepares evidence for human review. It does not certify conformity, issue CE marks, or replace a notified body or auditor.

Source markdown on GitHub

1. Problem framing

Software suppliers must show documentation and dependency hygiene against house rules or regulatory-shaped checklists. Spreadsheets drift. Cloud platforms move source of truth off the machine.

CyberReady+ is a local-first CLI. It evaluates packs (JSON rule sets) against a git repository, emits machine- and human-readable findings, and can bind a reproducible state digest into Git Notes. Judgment stays with people.

2. Architecture

Pack JSON → Validate engine → GateFailure IR (JSON + markdown)
                                    ↓
                         Review pack / evidence + optional attest

The engine is industry-agnostic. Packs are data. No remote policy brain is required for daily check. An optional Unix-domain socket bridge fails open if absent; the socket defaults to a private path mode 0600.

3. Packs as data

Packs ship embedded and may be overridden via CYBERREADY_PACKS_DIR. Schema validation rejects unknown checks and pathological regex at load. Network updates require a sha256 pin; air-gap import is preferred.

4. Dual representation

Every run produces JSON GateFailure IR and semantic markdown. Exit codes: 0 pass, 1 gates/error, 2 usage/environment.

5. Evidence artifacts

ArtifactRole
Review pack layersGate JSON, action report, executive summary
Buyer one-pagerSingle-screen snapshot (not a certificate)
CycloneDX / OpenVEXBest-effort SBOM; pending VEX drafts
HPURL + Git NotesLocal hash pointer; optional signature

Daily check does not generate or open the one-pager. prepare-release skips rewrite when the gate fingerprint is unchanged.

6. Trust boundaries

Signed means a real SSH signature. Unsigned means not cryptographically verified — never labeled as verified install. Install scripts and the Action verify release checksums fail-closed.

7. Non-claims

No conformity certification, CE marking, notified-body replacement, or claim that green gates equal market access.

8. Limitations

Pack quality bounds coverage; regex checks are heuristics with size/time guards; Windows is unsupported for release binaries and the sock bridge; client-side HPURL verify is not a remote notary.
